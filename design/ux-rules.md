# UX rules
Lead with the primary task and enough context to decide. Use progressive disclosure for optional
advanced settings. Keep related information and actions together. Prefer contextual creation when
the parent is already known; show parent context without forcing users to reselect it.
Reduce unnecessary questions and repeated data entry. Preserve filters, scroll, input and context
after errors or return navigation where feasible. Make save behavior explicit and consistent.
Show destructive impact before confirmation; label actions with verbs and the target.
Use short specific error messages and an actionable next step. Avoid "Something went wrong" alone.
Account for permissions, unsaved changes, duplicate submission, stale data and unavailable network.
Do not use technical database/status messages as product UX copy.
